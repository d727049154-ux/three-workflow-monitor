## Answer

完整面板按实时任务、工作流、资源和历史切换，编辑器保持挂载；每页保留焦点和滚动位置。历史沿用 04 的递增导航意图，新增返回已读历史内容的恢复入口，切页不会重新建立历史阅读 DOM，旧响应不能抢回页面。F5/Ctrl+R 改为刷新数据。实时任务按钮保留身份；观察时间不再使详情失效，无变化轮询保留详情、焦点和滚动。保存入口改为“保存当前观察”。来源支持用户保存显示名称，沿用已存在的 Source.title。

完整面板、摘要和任务条都呈现同一个 Backend 的任务事实；需要介入、正在推进、最近结束按明确 execution 分组。来源不可读、补读或暂停观察时显示“上次确认”，不会把暂停观察称为暂停执行。任务条初始为 108 逻辑像素窄轨，可展开到 440 查看详情或历史；接入、工作流与资源配置留在完整面板。

Rust 窗口层提供拖动、置顶、摘要、任务条展开/收起、左右贴边、显示/隐藏、找回窗口和退出；托盘提供显示/隐藏两个窗口、找回及退出。动态 WebView 创建保留异步命令，托盘与第二实例均异步调度。窗口动作使用独立异步队列，界面回调不等待该队列；调用 UI 的过程中不持有窗口偏好锁。X 隐藏窗口，两个窗口均隐藏时仍每五秒通过同一 Backend 观察。正常退出先停止接受新工作，等待已接收的后台调用及导出完成，再保存偏好和退出。

windows.json 使用与 Backend 相同的 resolved data_dir，包括明确绝对路径覆盖。位置按可用显示器工作区夹取，找回可重置两种窗口的位置；摘要不覆盖完整高度。无效或不可读偏好保留原文件，运行时提供临时默认窗口并显示无法保存的提示，后续动作不会覆盖坏文件。加入已授权的 single-instance 依赖，未扩大原生能力或路径权限。

定向验证：Rust windows 集成测试 4/4，通过公共 WindowStore/Bounds/Writes 验证选定目录重开、坏偏好只读保护、负坐标与失去显示器后的夹取、正常退出等待已接收工作。Node 测试 5/5，覆盖 04 的倒序/失效响应、返回已保留历史、实际观察渲染器的按钮/详情身份与阅读位置、坏来源和补读状态。app/observation 语法检查通过。DOM 测试使用浏览器边界替身，不替代真实 WebView。

原生验收待主代理：实际拖动/置顶/摘要/任务条贴边及展开、托盘、第二实例、退出重开、编辑草稿/焦点/滚动与刷新键、两窗事实一致、隐藏后的观察持续性。多屏与不同 DPI 尚未实机覆盖；本票未运行全量构建和全量测试，因此原生交互及真实 WebView 两项暂不勾选。

主代理原生验收发现主窗口摘要状态串入任务条：Tauri 2.10.3 的 window.emit 实际广播到所有窗口。已将 window-presentation 唯一发送点改为 emit_to(target, ...)，使 Rust 目标窗口成为展示事件的唯一接收者；前端不增加重复过滤。主代理已实测置顶、摘要、任务条 108→440 展开和右侧工作区贴边可用；定向事件修正已重建复验，两窗状态隔离通过；本票待剩余手工验收。

主代理原生复验：置顶、摘要、任务条展开/右贴边、窗口间状态隔离、摘要重开恢复、刷新与跨页面保留控件/草稿/焦点、隐藏两个窗口后继续观察、第二次启动仅一个进程、正常退出均通过。实机可用两块显示器，均原生 scale=1；WebView DPR=1.25。物理拖动、托盘菜单、实际跨屏移动及不同系统缩放由用户手动验收。用户最新授权先完成非界面发行与构建，以上手工项不阻塞第 06 票自动化部分，但本票不虚报 resolved。
