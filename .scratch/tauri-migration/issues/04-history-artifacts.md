## Answer

Rust 使用不可变的逐条历史记录及连续 hash 链；每条记录以独占临时文件写入、同步后原子发布，不重写旧记录。公开任务、来源身份、执行/验收、来源事件时间、观察时间及工作流/阶段引用按白名单保留，不保存整个 workspace 或资源正文。刷新指纹排除观察器时间；公开证据、状态及来源健康变化进入历史，checkpoint 始终独立，已读元数据另行追加，不争用工作区 revision。单条历史上限为 4 MiB，与工作区 512 KiB 上限分开；损坏记录阻止追加、校验与导出，并保留实时观察和具体错误。

完整面板和任务条共用 historyList/historySnapshot/historyCheckpoint/historyAcknowledge/historyVerify/historyExport。列表使用 beforeId 稳定游标，新增记录不移动后页。前端所有导航共享递增意图；返回实时、切换快照、重进列表或卸载会使旧响应失效，自动刷新不重建正在阅读的历史 DOM。历史详情展示当时状态、变化和公开文字，另列当前文件入口。文件只从公开文字中的 Markdown 链接/行内代码路径提取，基于记录中的任务根目录做 canonical 边界检查；缺失文件显示不可用，打开命令仅接收任务和文件引用 ID，由 Rust 解析后以固定 Explorer 参数定位。

导出必须明确选择 1–100 份快照，先按所选文件大小预检 8 MiB，再校验和读取；导出公开文字与本机路径，不复制媒体/工程，也不包含资源正文、工作区提示词或配置凭证。保存使用原生文件选择框和新文件名，不覆盖已有文件。本票不提供旧独立版格式导入，不改写旧来源和旧记录。

本票验证：Backend::call/save-reopen 的 Rust history 集成测试 7/7 通过，覆盖去重、重开及来源清空、独立 checkpoint/已读、选择性导出及隐私边界、当前文件缺失/路径逃逸、hash 损坏保护、非法 Unicode 标识和导出容量预检、追加期间的稳定分页、来源健康/公开证据/成果验收独立变化。真实前端导航控制器的可控异步测试 2/2 通过，覆盖切实时、快照响应倒序、重新进入列表及卸载。history/app/observation 的 Node 语法检查通过。

实现时的验收边界：原生 WebView 的历史→实时→文件闭环、Explorer 定位、原生导出选择框、实际窗口重开由主代理串行构建和演示后收口；本票未运行全量构建/全量测试。

主代理原生验收：Windows 构建成功，隔离目录中退出重开后历史仍可读；无变化刷新去重、独立 checkpoint、历史与实时切换、阅读 DOM 保留、当前文件引用及 hash 校验通过。原生保存框实际写出一份所选快照，解析导出文件确认不含手工资源提示词正文。文件定位命令已在前票验证发出，最终发行再核对实际文件夹选中状态。
