# 01: 从空工作区接入并观察一条真实任务

**What to build:** 启动 Tauri 原生应用，选择一个本机来源，在完整面板和任务条看到同一条真实任务及公开进展。

**Blocked by:** None。

**Status:** resolved

**审查对应:** F01、F05、F06；首次接入、共享任务事实。

- [x] Rust 经受限 Tauri 调用连接两种界面；随运行闭环交付来源/任务身份、执行状态、来源健康、事件/观察时间和验收契约。
- [x] 干净启动为空，不读旧配置或作者目录，不显示固定业务类；用户选择并启用来源。
- [x] Codex 公开进展和通用项目进度不依赖专用业务目录，保留线程/目录核验，不把推理或工具结果当公开进展。
- [x] 大工具行前后生命周期被完整消费，不完整 UTF-8 行下一次继续，补读可见，不虚构百分比。
- [x] 坏来源局部报错，健康来源继续更新，暂时故障不覆盖最后确认的执行状态。
- [x] 切换至空来源或清空来源后移除旧任务及当前产物缓存；同源暂时故障可重试恢复。
- [x] 验证新回合、大记录、不完整行、身份不符、坏/好来源共存和切换来源，并演示接入与刷新。

## Answer

Rust 观察服务、空态接入和共享 main/dock 已实现。公共接口测试 7/7 通过；Windows 原生构建成功，在独立数据及 WebView 测试目录实际验证空启动、项目进度保存/读取、重开、刷新、任务条创建及真实 Codex 公开进展读取（5 条公开消息，无推理内容）。实测修复了同步创建任务条导致的 Windows 卡住。

当前执行环境拒绝默认 AppData 写入，原生验收显式使用 WORKFLOW_MONITOR_DATA_DIR 与外部 WebView 测试环境变量；产品默认仍为系统应用数据目录，不自动回退。覆盖路径必须为非空绝对路径，解析测试通过。原生文件/聊天打开的完整交互在票 06 最终验收。
