# 02: 自定义工作流与阶段保存后可重开

**What to build:** 用户定义任意项目、工作流和阶段，接入通用进度文件，编辑保存后退出重开仍能正确观察。

**Blocked by:** 01（共享任务、来源与 Tauri 服务契约）。

**Status:** resolved

**审查对应:** F02、F04、F05、F09；通用工作流模型。

- [x] 移除固定业务类、专用配置及解析分支，名称、阶段、路径和关联规则由用户配置，不保留作者预设。
- [x] Rust 校验、版本冲突检查、持久化和编辑器形成闭环，保留输入限制、路径边界与不可读配置处理。
- [x] 阶段 ID 与顺序分离；重排/插入/改名不改变旧任务含义，删除阶段明确标记未知/已删除，保留标签及数量校验。
- [x] 序列化后按共同字节上限检查，归档/替换前拒绝超限，失败不损坏上次配置；旧超限/损坏文件显示恢复方式，不重置覆盖。
- [x] 旧格式仅在用户选择后兼容，明确不支持字段，不自动导入旧个人配置或改写历史。
- [x] 刷新保留草稿，冲突不丢输入；一个坏项目不阻塞其他项目。
- [x] 以两种无关业务命名的流程验证创建、编辑、保存重开、阶段身份、超限拒绝及冲突。


## Answer

原生产品已提供通用工作流创建、编辑、删除、暂停/恢复及接入模板。编辑器以独立 DOM 保留草稿和开始编辑时的 revision，刷新只更新列表；冲突后需显式选择最新版本再保存。阶段保持稳定身份，旧任务引用被删阶段时显示未知/已删除，进度文件中的子任务形成真实任务及阶段计数。

工作区和来源共用 512 KiB 读写上限，序列化超限在创建目录/临时文件及替换前拒绝。损坏、超限或含不支持字段的配置给出原文件路径及修复提示，禁止覆盖；仍兼容票 01 本应用原生 sources.json 数组格式。新应用不提供旧宿主工作区导入入口，不自动读取旧个人配置。

公共 Backend::call + 保存重开测试：workflows 8/8、observation 7/7 通过；覆盖果园灌溉与译稿出版、稳定阶段、暂停/恢复、坏项目隔离、有限 Unix 秒和带时区文本时间、序列化上限、原文件保留、工作区及来源双窗口冲突。前端相关模块 node --check 通过。

- [x] 主代理 Windows 原生界面验收：真实表单保存并退出重开、阶段名称与任务计数、原生模板复制、刷新保留草稿及焦点、过期版本保存时保留草稿并显示冲突，均通过。测试使用独立配置与 WebView 目录。
