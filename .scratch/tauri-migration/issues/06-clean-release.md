## Windows 构建标记修复（2026-11-11）

实际启动发现发行 EXE 继承开发目录的 Low 完整性标记，导致从资源管理器双击也以 Low 运行，无法写入默认的 Medium 完整性 AppData 目录，引发 WebView2 0x80000003 与拒绝访问。修正上一版 EXE 为 Medium 后，默认目录启动及历史写入已通过非界面检查；界面复验随后被用户中止。

构建入口现于复制最终 EXE 后用系统 icacls 将该文件设为 Medium；命令失败或不可用时构建失败并清理不完整发行目录。构建专项 8/8 通过，新增真实 Windows 回归用系统 whoami 可执行文件在 Low 目录下复现进程 Low 等级，并确认连续两次重建的发行进程均为 Medium；另覆盖命令失败及不可用的拒绝交付行为。

使用修正后的正式构建入口重新生成 0.8.0 release 成功。非界面核对确认最终 EXE 为 Medium，父发行目录仍继承 Low；发行目录仍为四个白名单文件，随包帮助与源 HELP 一致。本轮没有启动或操作应用界面，交互验收状态保持待验。
