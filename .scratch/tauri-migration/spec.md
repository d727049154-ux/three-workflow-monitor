## 目标与范围

项目根目录为 `C:/Users/yitian.li/Documents/ChatGPT/Matt 工作流插件`；规格和票放在该目录的 `.scratch/tauri-migration/`，产品源码位于 `three-workflow-monitor/` 子目录，沿用根目录的流程配置。

面向不同工作内容的本机工作流观察器，不绑定作者的三维制作流程、项目目录、技能集合或外部宿主。采用 Tauri 2 + Rust，保留完整面板、摘要、侧边任务条的呈现能力；为通用化、首次接入和审查问题调整界面。

运行时不依赖 Node、Electron 或 Token Monitor；读取、任务解释、配置、历史和系统交互由 Rust 承担。构建和前端测试可使用必要开发工具，不能把它们作为应用运行依赖交付。

本轮在 Windows 本地构建并实际运行验证。“通用”指业务用途、配置和模型通用，不增加 macOS/Linux 发行承诺，不扩展为支持所有 Agent 的平台。初始支持已有 Codex 公开会话与通用项目进度文件。

## 通用化要求

- 干净安装从空工作区开始。用户选择来源、项目/聊天或创建工作流后才观察；未接入时给明确入口，不显示虚构项目或预置业务工作类。
- 删除 Eagle、白模复刻、汽车制作等固有工作类和专用解析，包括配置字段、卡片、阶段列表、文件布局假设、技能分组、推荐提示词和个人业务示例，不作为隐藏选项或内置预设保留。
- 工作流名称、阶段及顺序、项目路径、资源及分类由用户定义，通过通用工作区和进度契约解释，不按业务名称分支。
- 移除固定用户名、盘符、作者目录、聊天 ID、技能清单、自动连接和开发机回退路径。不自动读取旧独立版/宿主数据，不扫描所有用户目录。
- 技能与资源按需接入用户选择的本机清单/目录；不要求 Skills Manager，不固化其 EXE、CLI 或目录。未配置不报错，已配置失效才提示；不另建通用连接器平台。
- 新应用使用自身数据位置，程序、配置、历史及导出边界清楚。旧数据不删除、不覆盖、不自动导入；用户选择读取旧格式时在读取边界兼容，明确不支持的专用字段，不静默套用个人配置或改写旧历史。
- 示例、测试夹具、帮助与分发同步通用化；用户数据及旧构建产物不进入新发行包。

## 统一事实与使用闭环

- 完整面板和侧边条共用任务事实，分别负责分组及注意力呈现，不各自推断生命周期。
- 执行状态、来源健康和成果验收分开；区分来源事件时间与观察时间。无日志更新不能独自证明失败，回合结束不能独自证明项目验收。
- 来源、线程/目录及阶段身份稳定。只消费公开进展和明确生命周期，不把推理或工具结果当公开进展，不从 token 使用或文件数量推算完成率。
- 可呈现需要介入、正在推进和最近结束；缺少明确等待/审批/失败信号时保持未知或待同步，不靠自然语言猜测。
- 首次接入完成“选择来源 → 一条真实任务及来源 → 查看进展 → 打开原聊天或结果”。如保留自动发现，先显示候选，选择后才启用。
- 历史说明当时观察到什么，当前文件入口说明现在能打开什么；不暗示历史文件版本已归档，不默认复制工程。

## 验证与依赖

每票贯穿 Rust、相关界面和行为验证，可独立演示，不将全部验证留到最后。保留受限本地调用、参数校验、路径边界、无 shell 拼接、安全文本渲染和导出隐私边界；坏数据不以空默认值覆盖。

周期刷新最多一个在途请求，不同配置写入和 checkpoint 不合并，无变化轮询不重复产生业务历史。性能先减少已证实的无效工作，再根据目标 Windows 实测优化，不把合成 CPU 基准当端到端结果。

01 真实接入 → 02 自定义工作流 → 03 可选资源。04 历史依赖 01、02；05 窗口与交互依赖 03、04；06 纯净发行依赖 01–05。前票随功能交付共用契约，不另建只有接口的票。最终验证 release 产物、托盘、原生打开、退出及重开；多屏等未覆盖环境如实说明。
