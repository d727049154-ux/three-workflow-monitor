# Domain docs

## Before exploring

Read the root `GLOSSARY.md` and any ADRs in `docs/adr/` relevant to the
area being explored. If they don't exist, proceed without creating them
upfront. Domain documentation can be created when terms or decisions are
actually resolved.

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md`: shared domain vocabulary.
- `docs/adr/`: architecture decision records.

## Vocabulary and decisions

Use the glossary's terms in issues, proposals, hypotheses and tests.
If a needed concept is missing, reconsider the terminology or note the gap
for domain modeling.

If a proposal conflicts with an existing ADR, identify the conflict
explicitly and explain why the decision may need revisiting.
