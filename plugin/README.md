# 工作流观察 0.5.0

Token Monitor 0.86.x 本机插件候选。看流程建设、任务细项和来源；查已有 Skill、工程资料、脚本、动作与调用方法。原生试装未验证，本机预览已实测。

## 常用操作

顶部“刷新”立即更新流程、任务、技能、资源和 Skills Manager，显示进行中与完成时间，保留筛选和展开状态。已关联进展仍每 15 秒自动读取，目录打开时每 60 秒同步。

“＋ 新建工作流”登记工程和环节，关联已有技能与资源；可按完整目录自动发现最近本机聊天，也可指定完整 UUID。新聊天每 60 秒发现；手动刷新立即发现。独立进度从工程根目录 `workflow-progress.json` 读取。“关联”中可复制接入用法，并暂停、恢复或编辑自定义流程。

“技能与资源”按工作流、分类、来源和文字筛选，展开后可复制调用示例、说明文件路径及配套资料。资源页支持“＋ 添加资源”，接入本机目录或单文件、用途、分类与调用说法。暂停扫描保留原始文件和关联；恢复后继续显示。

顶部快速查找覆盖任务、报告小项、技能、资源及其中的一级文件、制作专题、逐条动作和姿势。支持中文别名与近似匹配，精确名称和编号优先。弹窗焦点内按 `/`，↑↓ 选择、Enter 查看、Esc 返回。收藏与最近查看跨重开保存。具体文件可高亮并复制完整路径。

## Skills Manager 与范围

使用管理器发布的本机 CLI，只读中央库、标签、预设和客户端部署。CLI 返回账户根目录必须与配置一致；不将受限账户的空库当作用户中央库。SKILL.md 实际存在、管理器登记部署、文件内容一致和当前聊天已加载分开判断。完整目录保留本机、插件和系统入口。

资源与技能根在 `catalogFile` 指定的本机清单，自定义条目保存在插件数据目录。普通集合仅列一级、最多 80 项，不执行文件或加载大型工程。最多 40 条自定义流程、80 个自定义资源集合、64 个收藏。动作库按正式登记的默认版本读取完整目录并保留连续性提示，工程本体仅核对存在。

自动关联覆盖最近 200 条有标题的本机聊天，每流程最多 40 条；精确核对聊天 ID、会话头与工程目录，排除子代理。内置流程的任务清单继续有效。仅提取 assistant 公开文字与回合事件，不复制推理、工具原文、用户消息或图片。

## 回溯与恢复

变化追加编号快照，报告保存精确副本，聊天保存标注过的公开进展摘录。快照通过 SHA256 连接前序与来源，可校验、导出；查看旧快照不会回退制作文件。“最近变化”的已读只由用户主动推进到当前显示的位置。

用户配置采用原子保存并在 `workspace-history/` 逐版留档。目录与 Manager 记录分别存在 `catalog/`、`manager/`；配置和清单可导出到 `exports/`。遇到损坏配置保留原文件并报错，不用空配置覆盖。技术完成、视觉通过、用户接受分别显示。

宿主数据目录为 `%APPDATA%/Token Monitor/plugin-data/three-workflow-monitor`，以宿主实际提供路径为准。停用释放定时器，保留历史。预览可用项目 `停止预览.cmd` 停止；原生安装后通过宿主插件设置停用“工作流观察”。具体恢复步骤见项目的恢复说明。

## 权限与兼容

只读已接入项目、公开进展、技能与资源，写入自己的数据目录；不联网、不读取账户额度凭据、不发送消息或运行制作命令。点击打开入口才请求 Windows 打开登记目标；复制用法只是写入剪贴板。

包为 Token Monitor format-2 JSON/base64。插件 ID 继续使用 `three-workflow-monitor`，显示名改为“工作流观察”。代码通过同一前后端的本机预览与原生包校验器验证；Edge Dock、宿主 IPC、原生窗口响应和停用恢复尚未实测。

## 独立进度格式

由对应项目的任务维护文件；以下为格式示例，不是完成记录。ID 保持稳定，写临时文件后原子替换。总量未知时省略 progress。

```json
{
  "schema": "workflow-progress/1",
  "updatedAt": "2026-11-06T12:00:00+08:00",
  "state": "running",
  "stage": "制作",
  "summary": "第一镜制作中",
  "progress": {"completed": 0, "total": 2, "unit": "镜"},
  "tasks": [
    {"id": "shot-1", "title": "第一镜", "stage": "step-2", "state": "running", "detail": "正在检查相机", "updatedAt": "2026-11-06T12:00:00+08:00"}
  ],
  "acceptance": {"visual": false, "user": false},
  "issues": [],
  "facts": []
}
```

`state: complete` 只表示制作步骤完成，不能替代 visual 与 user 的独立确认。阶段 ID 和名称以该流程的接入用法为准。
