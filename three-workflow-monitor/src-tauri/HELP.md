工作流观察 · 使用帮助

启动
在 Windows 10/11 上运行 workflow-monitor.exe。需要系统已安装 Microsoft Edge WebView2 Runtime；无需 Node.js。首次使用为空，从完整面板接入来源。

接入与阅读
“实时任务”→“接入 Codex 聊天”：选择包含 JSONL 会话文件的本机目录，再选择一条聊天。
“接入项目进度”：选择包含 workflow-progress.json 的工程目录；文件须采用 workflow-progress/1 格式。在“工作流”创建后点“接入模板”，复制给当前项目的 Agent，按约定写入该文件。
选择任务后查看公开进展，通过“打开原聊天”或文件入口打开来源与当前文件。每 5 秒刷新，也可手动刷新；无更新不代表失败，回合结束不代表成果已验收。

工作流与资源
在“工作流”自定义名称、项目、来源和阶段。在“资源”按需登记本机文件或连接 JSON 清单；未配置资源不影响观察。暂停会停止相应观察，移除来源保留历史。

窗口与退出
“摘要”切换紧凑面板，“任务条”打开侧边条。关闭窗口会隐藏到托盘；托盘可显示窗口、找回窗口或打开帮助。使用“退出应用”或托盘“退出”正常关闭并完成保存。

历史与导出
“历史”可查看、保存或校验公开观察。选择记录后导出到新文件名，最多 100 条、8 MiB；仅含所选观察、公开文字、状态和文件引用，不含资源正文、提示词或文件内容。路径、标题与公开文字仍可能含私密信息，分享前检查。文件入口指向当前文件，历史不备份工程文件版本。

数据与恢复
程序目录仅放程序和随附说明。配置 sources.json、workspace.json、windows.json 与 history/ 默认保存在 %APPDATA%\local.workflowmonitor.desktop。导出位置由你选择。可在启动前用 WORKFLOW_MONITOR_DATA_DIR 指定绝对数据目录；它不会自动迁移数据。
更新程序保留原数据目录；不会自动读取其他程序的数据。配置损坏或超限时先正常退出，保留问题文件，再修复 JSON、权限或缩减内容（配置上限 512 KiB），或用你保存的同一应用有效副本恢复。历史校验失败应恢复完整、有效的 history/ 副本，不单独删改链中记录。没有有效副本时保留整个原目录，改用新的空数据目录重新接入。窗口失踪可从托盘“找回窗口”；窗口配置损坏时关闭应用，保留并移走 windows.json 后重开。
